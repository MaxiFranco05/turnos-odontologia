# Design: C-06 — Appointment Request & Transactional Anti-Overlap (`c-06-appointment-request`)

## Context

`C-02` (`core-models`) defined the `Turno` entity (`backend/app/domain/models/turno.py`), `EstadoTurno` (`solicitado`, `confirmado`, `anulado`, `cancelado`, `presente`, `ausente`), `OrigenTurno` (`online`, `manual`), SQLite anti-overlap triggers (`trg_prevent_turno_overlap_insert`/`update`), and `SqlAlchemyTurnoRepository` (`find_overlapping`, `has_overlap`). `C-03` and `C-04` delivered JWT authentication and `require_roles(*allowed_roles)` in `backend/app/api/deps.py`. `C-05` (`availability-engine`) delivered `PlantillaDisponibilidad` CRUD and the pure synchronous slot-partitioning engine (`calculate_free_slots` in `backend/app/application/availability.py`).

See `proposal.md` for motivation and scope, and `specs/appointment-request/spec.md` (along with `specs/scenarios-appointment-request.md`) for normative requirements and acceptance scenarios.

## Goals / Non-Goals

**Goals:**
- Expose `POST /api/turnos` restricted exclusively to authenticated patients (`RolUsuario.PACIENTE` with `debe_cambiar_password == False`), deriving `paciente_id` from the JWT session (`current_user.id`) and initializing `estado = EstadoTurno.SOLICITADO` and `origen = OrigenTurno.ONLINE` (`RN-TU-01`, `US-003`).
- Validate that the requested `[inicio, fin)` interval is strictly in the future in the clinic timezone (`America/Argentina/Buenos_Aires`, `RN-GL-02`, `CB-05`) and matches an exact, complete slot boundary (`duracion_slot_minutos`, `CB-02`) generated by the target dentist's `PlantillaDisponibilidad` (`RN-AG-02`).
- Guarantee zero double-booking on the server (`RN-AG-01`, `US-009`, Hard Rule #13) by combining transactional row locking (`SELECT ... FOR UPDATE` on active dentist appointments) with database-level integrity constraints (`IntegrityError` catch → `409 Conflict`).
- Strictly enforce all 13 Hard Rules in `AGENTS.md` (Pydantic `extra="forbid"`, SQLAlchemy 2.0 `select()`, synchronous `def` for pure in-memory slot validation, noun-based REST URI `/api/turnos`, real SQLite/PostgreSQL tests with zero mocks, and 100% synthetic test data).

**Non-Goals:**
- State transitions after creation (`confirmar`, `anular`, `cancelar`, `marcar-presente`, `marcar-ausente`) — scoped to `C-07` (`appointment-state-machine`).
- Manual appointment creation by Reception (`origen = manual`) — not part of `C-06` (`CHANGES.md` lines 200–206).
- Listing agendas or patient appointments (`GET /api/agenda/dia`, `GET /api/mis-turnos`) — scoped to `C-08`, `C-09`, and `C-10`.

## Decisions

### 1. Endpoint Contract & Security Boundary (`POST /api/turnos`)
- **Decision**:
  - Route: `POST /api/turnos` in `backend/app/api/turnos.py`, registered in `backend/app/main.py`.
  - Authorization: `current_user: Annotated[Usuario, Depends(require_roles(RolUsuario.PACIENTE))]`.
  - Request Schema (`TurnoCreate`):
    ```python
    class TurnoCreate(BaseModel):
        model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)

        odontologo_id: int = Field(gt=0, description="ID del odontólogo")
        inicio: datetime.datetime
        fin: datetime.datetime
        motivo: str = Field(min_length=1, max_length=255, description="Motivo de consulta")

        @model_validator(mode="after")
        def _validate_chronological_order(self) -> "TurnoCreate":
            if self.fin <= self.inicio:
                raise ValueError("fin debe ser estrictamente mayor que inicio")
            return self
    ```
  - Response Schema (`TurnoResponse`):
    ```python
    class TurnoResponse(BaseModel):
        model_config = ConfigDict(extra="forbid", from_attributes=True)

        id: int
        paciente_id: int
        odontologo_id: int
        inicio: datetime.datetime
        fin: datetime.datetime
        motivo: str
        estado: EstadoTurno
        origen: OrigenTurno
        creado_en: datetime.datetime
        actualizado_en: datetime.datetime
    ```
- **Rationale**:
  - **OWASP API1:2023 (Broken Object Level Authorization) & API3:2023 (Broken Object Property Level Authorization)**: Omitting `paciente_id`, `estado`, and `origen` from `TurnoCreate` combined with `extra="forbid"` (Hard Rule #1) prevents a client from booking on behalf of another patient or self-confirming an appointment.
  - `str_strip_whitespace=True` + `min_length=1` ensures whitespace-only strings (`"   "`) are rejected at the Pydantic validation boundary (`422 Unprocessable Entity`, `US-003 CA-2`).

### 2. Pure Synchronous Template-Slot Matching (`def validate_slot_matches_template`)
- **Decision**: Implement a pure synchronous function `def validate_slot_matches_template(inicio: datetime.datetime, fin: datetime.datetime, templates: list[PlantillaDisponibilidad], timezone_str: str, now_override: datetime.datetime | None = None) -> None` in `backend/app/application/turnos.py` (or reuse `calculate_free_slots` with `turnos=[]`).
- **Rationale**:
  - **Hard Rule #3**: In-memory datetime normalization and template grid verification perform zero async I/O and MUST use synchronous `def`.
  - **Algorithm**:
    1. Normalize `inicio`, `fin`, and `now` into `zone = ZoneInfo(timezone_str)` (`America/Argentina/Buenos_Aires`).
    2. Verify `inicio.date() == fin.date()` in clinic local time (a single slot never crosses midnight).
    3. Verify `inicio > now_local` (`RN-GL-02`, `CB-05`). If `inicio <= now_local`, raise a domain validation error mapped to HTTP `422 Unprocessable Entity`.
    4. Compute the valid template grid slots for `inicio.date()` using the dentist's templates for `inicio.date().weekday()` (stepping by `duracion_slot_minutos` while `slot_inicio + duration <= template_fin`, `CB-02`).
    5. Verify that at least one generated template slot has `slot.inicio == inicio_local and slot.fin == fin_local` (`RN-AG-02`). If not, raise a domain validation error mapped to HTTP `422 Unprocessable Entity`.
- **Alternatives considered**:
  - *Only checking `template_inicio <= inicio and fin <= template_fin`*: Rejected because it would allow arbitrary off-grid intervals (e.g., `09:10–09:40` or a 90-minute block on a 30-minute template), violating `RN-AG-02` and `CB-02`.

### 3. Transactional Anti-Overlap with `SELECT ... FOR UPDATE` and DB Trigger Fallback
- **Decision**: Add `async def find_overlapping_for_update(self, odontologo_id: int, inicio: datetime.datetime, fin: datetime.datetime, exclude_turno_id: int | None = None) -> list[Turno]` to `TurnoRepository` and `SqlAlchemyTurnoRepository`:
  ```python
  stmt = (
      select(Turno)
      .where(
          Turno.odontologo_id == odontologo_id,
          Turno.estado.not_in([EstadoTurno.CANCELADO, EstadoTurno.ANULADO]),
          Turno.inicio < fin,
          Turno.fin > inicio,
      )
      .with_for_update()
  )
  ```
  Additionally, wrap `await repo.add(turno)` and `await db.commit()` in a `try / except IntegrityError` block that rolls back the session (`await db.rollback()`) and raises HTTP `409 Conflict`.
- **Rationale**:
  - In PostgreSQL (`production`/`docker-compose`), `.with_for_update()` acquires row-level `FOR UPDATE` locks on candidate rows for that dentist, serializing concurrent reads/updates (`CHANGES.md` line 203).
  - In SQLite (`test` suite without mocks per Hard Rule #7), `WITH FOR UPDATE` is ignored by SQLite's parser/dialect, while the database-level `BEFORE INSERT` trigger `trg_prevent_turno_overlap_insert` (defined in `backend/app/domain/models/turno.py` lines 73–88) raises `IntegrityError` (`RN-AG-01: Invariante anti-solape violada para el odontologo`) if a race condition slips past the `SELECT` check. Catching `IntegrityError` and translating it to `409 Conflict` guarantees a deterministic `409` response in both engines without leaking `500 Internal Server Error`.

### 4. Standardized HTTP Status Code Mapping
- **Decision**:
  | Condition | HTTP Status | Rule / Reference |
  |---|---|---|
  | Valid appointment request persisted | `201 Created` | `US-003`, `CHANGES.md` |
  | Missing/invalid JWT | `401 Unauthorized` | `RN-AU-01` |
  | Role is `recepcion` or `odontologo`, or `debe_cambiar_password=True` | `403 Forbidden` | `RN-TU-01`, `RN-GL-01`, `US-010` |
  | `odontologo_id` does not exist in `usuarios` | `404 Not Found` | `CB-06` (consistent with `disponibilidad.py`) |
  | Overlapping active appointment (`solicitado`, `confirmado`, `presente`, `ausente`) | `409 Conflict` | `RN-AG-01`, `CB-04`, Hard Rule #13 |
  | Undeclared fields (`extra="forbid"`), empty `motivo`, `fin <= inicio`, `odontologo_id` not an `odontologo`, past/elapsed timestamp, or slot outside template grid | `422 Unprocessable Entity` | Hard Rule #1, `RN-AG-02`, `RN-GL-02`, `CB-02`, `CB-05`, `CB-06` |

## Risks / Trade-offs

- **[Risk] Timezone-naive vs. timezone-aware `datetime` comparison in SQLite**: SQLite stores timestamps as ISO strings and may hydrate naive datetimes depending on dialect configuration, whereas clients send ISO-8601 timestamps with `-03:00` or `Z`. → **Mitigation**: Normalize all incoming `inicio`/`fin` timestamps to `ZoneInfo(settings.TIMEZONE)` before persisting and before comparing against existing `Turno` rows in memory or SQL queries.
- **[Risk] Phantom read in `READ COMMITTED` when no row yet exists to lock with `SELECT ... FOR UPDATE`**: If two concurrent transactions request the exact same empty slot simultaneously, `SELECT ... FOR UPDATE` finds 0 rows in both transactions. → **Mitigation**: The database-level trigger (`trg_prevent_turno_overlap_insert` in SQLite / exclusion constraint in PostgreSQL) aborts the second `INSERT` with `IntegrityError`, which the endpoint catches, rolls back cleanly, and converts into HTTP `409 Conflict` (`US-009 CA-1`, `CA-2`).
