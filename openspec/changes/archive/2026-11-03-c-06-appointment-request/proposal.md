# Proposal: C-06 — Appointment Request & Transactional Anti-Overlap (`c-06-appointment-request`)

## Why

With the core domain models (`Usuario`, `PlantillaDisponibilidad`, `Turno`) established in `C-02`, JWT/RBAC authentication (`get_current_user`, `require_roles`) in `C-03`/`C-04`, and the dynamic availability engine (`GET /api/disponibilidad`, `calculate_free_slots`) delivered in `C-05`, patients can discover free time slots (`US-002`) but still lack the endpoint to submit an appointment reservation (`US-003`, `US-009`). Implementing `POST /api/turnos` closes the online booking loop (`Flujo 2`, steps 3–5) while enforcing the server-side non-overlap invariant (`RN-AG-01`, Hard Rule #13) and strict schedule-template derivation (`RN-AG-02`, `RN-GL-02`).

## What Changes

- **Patient Appointment Request Endpoint (`POST /api/turnos`)**:
  - Exposes `POST /api/turnos` (noun-based URI per Hard Rule #8), restricted exclusively to authenticated users with role `RolUsuario.PACIENTE` and `debe_cambiar_password == False` via `Depends(require_roles(RolUsuario.PACIENTE))` (`RN-TU-01`, `RN-GL-01`, `RN-AU-02`, `US-010`).
  - Derives `paciente_id` strictly from the authenticated JWT session (`current_user.id`) and never from the request payload, preventing Broken Object Level Authorization (OWASP API1:2023 BOLA/IDOR).
  - Accepts a strict Pydantic v2 payload (`TurnoCreate`) with `model_config = ConfigDict(extra="forbid", str_strip_whitespace=True)` (Hard Rule #1): `odontologo_id` (`int > 0`), `inicio` (`datetime.datetime`), `fin` (`datetime.datetime`), and `motivo` (`str`, non-empty after whitespace stripping, `1..255` chars, `US-003 CA-2`).
  - Validates chronological ordering (`fin > inicio`), verifies that `odontologo_id` exists (`404 Not Found` if missing) and has `rol == RolUsuario.ODONTOLOGO` (`422 Unprocessable Entity` if another role, `CB-06`), and rejects past dates or already elapsed time slots on the current clinic day in `ZoneInfo(settings.TIMEZONE)` (`America/Argentina/Buenos_Aires`, `RN-GL-02`, `CB-05`).
  - Validates via a pure synchronous helper (`def validate_slot_matches_template(...)`, Hard Rule #3) that the requested `[inicio, fin)` interval matches an exact, complete slot partition (`duracion_slot_minutos`, `CB-02`) generated by the dentist's `PlantillaDisponibilidad` for `fecha.weekday()` (`RN-AG-02`).
  - Executes a transactional overlap check (`SELECT ... FOR UPDATE` via `select(Turno).with_for_update()` on active appointments of the dentist + database-level anti-overlap trigger/constraint safety net) to reject any collision `[inicio, fin)` against existing appointments in state `solicitado`, `confirmado`, `presente`, or `ausente` with HTTP `409 Conflict` (`RN-AG-01`, `CB-04`, Hard Rule #13), while allowing booking over slots whose previous appointments are in state `cancelado` or `anulado` (`RN-TU-04`, `CB-03`) or contiguous adjacent intervals (`fin_A == inicio_B`, `CB-01`).
  - Persists the new `Turno` with initial state `EstadoTurno.SOLICITADO` (`US-003 CA-1`: never confirmed directly) and `origen = OrigenTurno.ONLINE` (`US-003 CA-3`), returning HTTP `201 Created` with the created appointment representation (`TurnoResponse`).

### New Capabilities
- `appointment-request`: Patient-initiated online appointment reservation (`POST /api/turnos`) with strict schedule-template slot matching (`RN-AG-02`), clinic timezone future-time validation (`RN-GL-02`), and transactional server-side anti-overlap enforcement (`RN-AG-01`).

## Impact

- **Domain & Infrastructure Repositories**: Extends `TurnoRepository` (`backend/app/domain/repositories/turno.py`) and `SqlAlchemyTurnoRepository` (`backend/app/infrastructure/repositories/turno.py`) with `find_overlapping_for_update(...)` using SQLAlchemy 2.0 `select(Turno).with_for_update()` (Hard Rule #2).
- **Application Layer**: Adds `backend/app/application/turnos.py` containing pure synchronous slot/template validation (`def validate_slot_matches_template(...)`, Hard Rule #3) and transactional appointment request orchestration.
- **API Layer**: Adds `backend/app/api/turnos.py` (`POST /api/turnos`, `TurnoCreate`, `TurnoResponse`) and registers `turnos_router` in `backend/app/main.py`.
- **Tests**: Adds `backend/tests/test_appointment_request.py` executing against a real SQLite in-memory database without mocks (Hard Rule #7) and using 100% synthetic test data (Hard Rule #12).
